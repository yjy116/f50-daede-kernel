# 完整官方更新与配置保留政策

用户要求保留当前可用配置；新的明确修改要求优先。每次升级使用当时设备的最新
设置，不得用 2026-10-11 的基线覆盖之后修改的密码、订阅或网络参数。
2026-10-31 的新要求是后续进行完整官方更新，使用已经包含 BPF JIT/BTF 的官方内核，
不再为本设备编译或部署本仓库的旧自定义内核。完整更新仍须先完成配置、插件和恢复验证。
本次执行结果及未完成验收见 [官方升级报告](releases/f50-official-20261031.md)。

1. 检查运行版本、服务状态及未提交 UCI 修改；在设备运行已安装的
   `/etc/mu300/f50-profile/capture.sh` 创建唯一目录的新快照。Honk 将短暂停止并恢复。
2. 下载到私有目录。临时维护公钥不得留在长期备份：只删除本次公钥的精确匹配行，
   保留其他授权。生成与 `tools/verify_snapshot.py` schema 一致的清单，核验双端
   SHA、必需路径、SQLite 和隔离恢复。保留上一次验证成功的快照。
3. 核查候选镜像和实际系统差异。原生 `mu300-update apply` 不读取
   `sysupgrade.conf`/`keep.d`，会执行 boot_update；备份集成不等于升级保留。
4. 默认准备完整官方 rootfs 和官方内核包：固定 Release、commit、资产摘要与签名公钥，
   验证发布签名和实际包内容。在隔离候选系统中合并最新用户设置、定制文件，安装兼容插件
   和依赖并完成真实 APK 求解后再切换。优先使用新官方 feed；确有版本约束时可保留已验证
   的社区包或旧用户态配套包，并记录原因。禁止因此降级新基础包或安装其他内核的 kmod。
   不整体覆盖 `/etc`，不恢复旧 APK 数据库或旧 world；`image-version`/`packages.txt` 保持新版本。
   对重新出现的首启脚本逐项核对：已执行的同版本初始化不得再次重置配置，新版本迁移也
   不能整目录删除。记录执行、跳过理由和结果，随后恢复用户原有服务启停状态。
5. 保留 Honk 的 SIPA 修复、Doona 数据库、认证/订阅/路由/DNS、热点/蜂窝、设备身份、
   LuCI 温度 ACL/脚本、Doona 入口及服务启停状态。设备脚本优先采用经核对的官方实现；
   本次 `mu300-hw` 使用新版官方原文，旧定制仅作为备份，不覆盖或运行旧脚本。当前 daede 已卸载、
   OpenClash 保留但停用，不得因恢复旧配置而重新启用。用户已允许在确认 Honk 不兼容时
   改用 daede；此时先保留原配置和认证数据，明确订阅、路由、DNS 与界面的迁移方式，
   验证实际代理后再替换，避免两个代理同时接管网络。当前升级仍使用 SIPA 适配 Honk/Doona。
   电脑继续优先通过 WLAN 上网，USB 用于管理。新增服务默认值也属于迁移差异：本设备
   使用官方 `/etc/mu300/adb=off` 保持原有无 ADB 的 NCM/串口管理方式，不能因升级缺省值
   自动开放未认证 root ADB。
6. 单独保留所选官方内核包及匹配的模块、BTF、设备 boot 材料；核查 JIT/BTF 和 SIPA 能力。
   同时检查代理实际需要的 hooks、进程识别和规则语义。JIT/BTF 开启或接口 attached 不等于
   全部兼容；如 API 报告能力降级，必须说明受影响的现有规则并完成评估，不能忽略该状态。
   旧自编内核与工作流只作历史追溯，不作为后续编译或部署目标。官方候选不满足要求时，
   记录不兼容并选择受支持的官方版本或代理方案，不以临时自编内核或异版模块替代。
   `MU300_KERNEL_BUNDLE` 不是无条件跳过 boot 刷写，需核对候选源码和 installed.id
   条件。同步保留工具中的 kernel bundle 路径/SHA，保留回退材料，并独立读回 boot 正文、
   尾部和写入区域。写入命令的非零退出必须原样记录，不能仅靠脚本状态推断刷写成败。
7. 切换前核验设置、认证数据库、定制文件和依赖；启动后检查 Honk/Doona、温度、
   菜单、热点、订阅、节点真实 HTTP/UDP DNS 及手机代理访问。进程存活或 API
   operation succeeded 不等于代理正常。无 SIM 时可以完成系统、插件、界面和内核检查，
   但蜂窝与经蜂窝的真实代理流量必须标记待验收，不能继承旧版本测试结果。
   实网验收分别记录插卡与带卡重启后的结果，核对 boot ID 和 WAN 自动恢复；逐节点探测
   使用独立时限，保留首次失败、共享 deadline 与后续复测记录。在线订阅刷新可能改变
   运行时节点 ID，须重新发现节点并复测，不能以旧 ID 或刷新前结果代替。手机验收关闭移动数据。
   ZeroTier 在线不等于目标网段可达：发生故障时检查实际路由、下一跳邻居状态及目标响应，
   区分观察到的暂时中断与已证实根因；未修改服务即恢复时也保留前后证据，不宣称永久修复。
8. 保存验证证据。撤销本次临时 SSH 授权，确认新连接认证被拒绝，再删除本机临时密钥。
   若同步 GitHub，源码和摘要可公开；包含秘密的材料必须加密后作为 Release 附件，
   解密密钥仅由持有人私下保管。每次使用独立 Release 标签，上传后重新下载、校验并解密验证；
   不覆盖 `f50-profile-20261011` 或其他历史标签。普通 `.gitignore` 不能替代逐文件发布检查。

本次带 SIM 重启后的实网验收通过；历史偶发节点回程丢包尚未证明永久消除，
不能以单次成功或自动重拨隐藏故障。
历史 v17→v18 脚本是特定前提下的迁移记录，不应直接用于下一版本。
