F50 ZeroTier 中文界面 p2：VPN → ZeroTier → 配置 / 接口信息

复用主项目总台账16–18。界面布局按用户参考图补齐；不复制参考图的Network ID、开关状态或密钥。使用 LuCI 原生控件和仅在 ZeroTier 页面生效的浅灰背景、圆角卡片与表格样式；不替换全站主题。
前端源自 ImmortalWrt luci d6167ea0645cbd1327708d85f94824f42d0eb872，保留 GPL-3.0-only 和原版权。后端适配见 ../zerotier-backend/。

配置与状态
- 实时状态条；全局启用、监听端口、客户端密钥、本地配置路径、配置目录、复制目录、守护进程入站开关、ZeroTier 管理中心链接。
- 具名网络表：启用、网络ID、四个allow选项、入站、转发、IP动态伪装。
- 原有未设置 network.enabled 的网络继续默认启用，符合旧官方后端语义。
- 新 fw_* 默认0，只控制本服务附加规则，不撤销用户已有的手工防火墙规则。
- copy_config_path仍默认0，保留官方原语义，不照参考图改成1。
- 客户端密钥框始终为空，现有身份不会进入输入框。留空保存不改旧值，只有明确输入新密钥才替换；页面不会读取 identity.secret 文件。
- 接口信息显示节点公开状态、网络状态/接口/地址。CLI错误和RPC失败直接显示，不能把服务运行误报为已获网络授权或可通信。
- ACL保留 exact CLI -j info / -j listnetworks、service.list、zerotier UCI，不授予裸CLI、join/leave/set或通用文件读取权限。

构建与依赖
- UI：luci-app-zerotier 1.1.0_p2-r1，noarch。
- 精确依赖 zerotier=1.16.0_p2-r1、luci-base、rpcd-mod-file。
- 核心p2保留官方1.16.0二进制、配置模板及符号链接，仅更改审查过的init/helper/生命周期脚本和包元数据；不能把UI单独装到p1后端。
- GitHub Actions → F50 Chinese ZeroTier LuCI：固定成功内核证据确认TUN=y，两包分别构建/审计/临时密钥签名，输出backend/和ui/两目录。
- 每包导出自己的公钥；安装时两个公钥使用不同文件名放入临时keys目录。不覆盖系统信任库，不关闭验签，不导出私钥。

安装行为
- UI没有/etc/config或uci-defaults；post-install只走标准UI生命周期和刷新LuCI缓存、rpcd/uhttpd，管理页会短暂断开，随后可重新登录。
- 核心p2更新不会执行default_postinst，它会无条件启动init并提交所有UCI。仅注册原包用户，保留已有boot links和配置，不启动守护进程或加入网络。
- 此核心升级针对已经安装p1的F50；不是通用官方发行包，也不声称新装设备的开机服务状态已验证。实际启用/停用发生于用户保存应用或开机流程。
